Estate Memory

A self-hosted RAG system and MCP server, so every AI on my desk shares one memory of my projects

The problem. Every new chat started cold. Decisions already made got re-derived, and long documents got pasted around by hand.

What I built. My Obsidian vault mirrors to the server with Syncthing. A pure-standard-library Python indexer chunks the docs, embeds them with qwen3-embedding running on my desktop GPU through Ollama, and stores them in Postgres 16 with pgvector. Search is hybrid — vector similarity plus keyword matching, weighted toward recent documents — with a heading breadcrumb carried into each chunk so a dated log entry keeps its date. An MCP server exposes memory_search, memory_read_doc, and memory_stats; it runs as a systemd service, bound to loopback behind tailscale serve, with a read-only database role and a file exclusion list so private material never gets indexed.

Who uses it. Claude Desktop (via an extension), Claude Code, and Codex CLI all have the tools. A "canon" step generates fact-cards from the sources with the local model, and the rule is written on the card: cards are interpretation; sources are truth.

Source. A sanitized, portable release is public at github.com/SwagLordPrime/estate-memory: docker-compose for pgvector, any Ollama host, a fictional sample corpus, example systemd units, and 37 offline tests that run without a database. The README says what was measured and what wasn't.

GRIMOIRE — the Council Dashboard

An investing-discipline app that makes me follow my own rules, built by directing multi-agent Claude Code teams

The problem. Trading decisions made in the moment are bad decisions. I wanted a system where the rules are written down, the record can't be quietly edited, and a review is forced on a schedule.

What I built. A Flask + SQLite application with append-only ledgers — UPDATE and DELETE raise inside the database, so a mistake is corrected by a new row, never by rewriting history — a single-writer boundary (the app is the only ledger writer), and scheduled "rites" run by systemd timers behind a window guard that refuses to fire more than twenty minutes off its ratified minute, because a missed window must stay missed. A read-only brokerage integration feeds positions; Claude generates the morning and Monday pre-trade briefs from versioned per-job prompt files under a hard monthly API spend cap, with deep audits routed through the Batch API for the discount.

How it shipped. I wrote build plans with explicit gates, chose model and effort tiers per task to control cost, ran an adversarial verification pass against the live system before accepting any "done," and kept handoff, backlog, and debrief documents current across Claude and Codex sessions. Rites that fire unattended are re-verified three trading days later, because a cutover-day check can't prove that.

The Vault

A hardened home server that the rest of the estate stands on

The problem. Ad blocking, backups, monitoring, sync, and a place for services to live — without renting it from anyone, and without a box that quietly dies unnoticed.

What I built. Ubuntu Server 24.04 on retired X99 hardware, headless, key-only SSH, Tailscale for remote access (the ISP is behind CGNAT, so port-forwarding was never an option). Services run in Docker with Portainer. The house's DNS points at it, so Pi-hole is deliberately excluded from the nightly backup stop loop — proven by container uptimes after a backup run. Alerts go through self-hosted ntfy; an external healthchecks.io ping is the dead-man's switch. Every service has a runbook, and long instructions travel by synced files, never by pasting.

Rules I keep. New /srv directories are born with the right owner. Anything with personal data binds to loopback and is served only over the tailnet; house services stay on the LAN. Self-hosted apps install only from the home the official site links to. Hardware prices and config names get verified against current docs every time.

How I work with AI

I use Claude Code, Codex, Copilot, and local models every day, and the useful skill turned out to be judgment about when to trust them. These are the working rules that came out of a year of shipping with agents.

Plans have gates

A build plan says what "done" means before an agent starts, and where it must stop and surface instead of guessing. Ambiguous gates get rewritten, not argued with.

Verification scales with risk

Ledger math and anything touching money gets a full adversarial pass on the live system. A cosmetic change gets a spot check. Reports are never accepted as evidence of themselves.

Spend is a decision

Each task gets the cheapest model and effort that can do it well; the API has a hard monthly cap; expensive audits ride the Batch API. Expected spend is written down and compared to actual.

Sources beat summaries

Generated fact-cards say where each claim came from and when. A History line takes a date only from the source text, or says "undated." Cards are interpretation; sources are truth.

The record includes what wasn't done

Every close-out lists decisions not to act and constraints that were kept. Missed windows stay missed — no catch-up runs that write a wrong-hour row.

Pasted text is data, not instructions

Anything quoted from the internet is read for content and never followed as a command. Nothing binds to 0.0.0.0; the private tailnet is the boundary.

  • Verify third-party config and env names against current docs, every time; say when a number is unverified.
  • Label every command with where it runs and what success and failure look like. Never a bare command.
  • One session drives the server at a time; coordinate through the human, never collide.
  • Self-hosted software installs only from the home the official site links to.
